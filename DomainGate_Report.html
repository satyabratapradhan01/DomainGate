1. Executive Summary

DomainGate is an enterprise cross-platform Zero-Trust Identity and Access Management (IAM) application engineered to enforce strict, cryptographically validated corporate access boundaries.

The core security mission of DomainGate is exact domain-based authorization: only users authenticated through Google OAuth whose verified corporate email strictly ends with @hbplus.fit are granted entry into the internal dashboard. Any unauthorized domains (such as @gmail.com, @yahoo.com, or spoofed subdomains like user@sub.hbplus.fit) are immediately quarantined, purged from memory, and rejected at both the application router and Cloud Firestore database levels.

3. Technical Highlights & Enterprise Capabilities

  • Multi-Platform OAuth Orchestration: Seamless Google authentication across Web (Firebase signInWithPopup) and Mobile Android/iOS (Expo AuthSession OIDC PKCE flow).
  • Defense-in-Depth Domain Enforcement: Strict regex validation rejecting consumer webmails, foreign corporate domains, subdomain spoofing (attacker@sub.hbplus.fit), and suffix spoofing (malicious@hbplus.fit.evil.com).
  • Cloud Firestore Database-Level Rules: Backend security rules reject all read and write queries from non-@hbplus.fit tokens; prevents self-escalation of roles.
  • Flicker-Free Session Persistence: Secure token storage via AsyncStorage and expo-secure-store with expiration validation on app reload.
  • Immediate Emergency Purge: Zero-delay session teardown on authorization failure—unauthorized tokens or cookies never linger in storage.
  • Built-In Evaluator Sandbox Test Rig: An interactive test harness built directly into the Login screen allows evaluators without an @hbplus.fit inbox to test authorized, unauthorized, and unverified scenarios with cryptographic simulation.

5. Engineering Lessons & Takeaways

A. Cross-Platform OAuth Discrepancies (Web vs. Android Expo Go)

Developing OAuth for both Web and Mobile highlighted the fundamental difference between browser popup windows and mobile deep-link proxies:

  • Google Cloud Console creates two distinct OAuth client types: Web Application and Android Application.
  • An Android Client ID in Google Cloud validates native APKs via package name (com.domaingate.auth) and SHA-1 certificate fingerprint, and does not accept HTTP redirect URIs.
  • In Expo Go, Google Sign-In is executed via an in-app browser using the auth.expo.io proxy. Therefore, Expo Go must utilize the Web Client ID with the authorized proxy redirect URI (https://auth.expo.io/@satyabratapradhann/DomainGate) to avoid Error 400: redirect_uri_mismatch.

B. True Zero-Trust Implementation

In real-world enterprise architectures, client-side validation is merely a UX convenience. True gating requires synchronized client boundary evaluation, backend database rules, and automatic session purging on any anomaly. DomainGate achieves defense-in-depth across the client UI, OAuth provider claims, and Firestore security rules.
